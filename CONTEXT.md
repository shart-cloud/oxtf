# Domain language

This glossary records the concepts sharpened during the architecture review.
Existing implementation decisions and spike limitations remain in `SPIKE_REPORT.md`.

- **Expression collection admission**: evaluator literals, splats, comprehensions, arguments, alternatives, catches, and template buffers reserve logical payload against the active scan's `collection_bytes` before growth or copying. Borrowed iteration and stack bindings need no collection payload. Refusal remains sticky across catches, caches, roots, and workers; sensitivity, prior errors, and uncertain dependencies survive. Semantic conversion and analyzer models extend this allowance; public low-level value APIs remain outside it. The full contract and exclusions are in `docs/LIMITS.md`.

- **Analyzer model admission**: model/instance builders, per-root memo tables, expansions and resource/module/body/IAM projections reserve `collection_bytes` before allocation. Source collections are borrowed for expansion. Unfinished bodies are discarded; completed resources remain available alongside terminal `coverage-storage`. Every newly constructed model pays even with warm definitions or disabled retention. Parsed indexes/store-entry metadata, graph/provenance, plan models and live retained-memory admission remain separate; see `docs/LIMITS.md`.

- **Contextual function**: a Terraform function evaluated through the module resolver because it needs the scanned root and file snapshot (`file`, `templatefile`, file hashes, `abspath`). Text overlays win over disk; binary hashes read bytes without text decoding. Templates bind only their supplied variables and lexical iterators. Explicitly fetched packages retain their recorded file-read boundary. Unhandled expression errors are failed analysis, distinct from provider-computed unknowns and coverage limits.

- **Resource instance**: one managed resource or data-source instance in the owned analysis model. Its identity includes its module instance and its `count` or `for_each` key; a base address alone does not identify an expanded instance.
- **Resource reference**: a value used to identify a resource instance. Known identifiers match by value; computed references carry an address, instance key, and attribute. Matching can be definite, impossible, or uncertain.
- **Explanation provenance**: the source locations and dependency steps explaining a value. Sharing provenance does not prove equal values or equal resource identity.
- **Rule catalog**: where a scan's rules come from, resolved in order: the bundled catalog, the seed rules, rule-IR files and documents, runtime rules (Python callbacks), then Rego policies. A later source shadows an earlier rule of the same name, which is how a user's rule-IR or Rego rule replaces a seed rule of the same name and a user's Checkov policy replaces the bundled one with its ID. `tf_scan::Catalog`; `Catalog::standard()` (bundled + seed) is what the CLI and Python run by default.
- **Bundled catalog**: the Checkov pack and Checkov's graph policies, generated at a pinned version (3.2.328) into `crates/tf_rule_ir/data/checkov/` and compiled into the binary (`tf_rule_ir::bundled`). Each rule is compiled the first time it judges, so a scan pays only for the resource types it meets. On by default; `--no-bundled` / `bundled=False` drops it, `--no-builtin` / `builtin=False` drops it and the seed rules. Regenerated, never hand-edited; `tests/bundled.rs` fails when it is stale.
- **Profile**: what kind of problem a shipped rule finds — `security` (exposes, weakens, over-grants), `audit` (visibility: logging, retention), `hygiene` (cost, tags, style, reliability), or `unreviewed` (a bundled rule not curated yet, which runs with `security`). A scan runs the `security` profile unless `--profile` / `profiles=` says otherwise; an explicit selection reaches every profile, and rules a caller loads always run. `tf_linter::Profile`, `Catalog::profiles`.
- **Curation**: `crates/tf_rule_ir/data/checkov/curation.toml`, oxtf's hand-kept level, category, profile and reason for bundled rules, applied at build time over the generated catalog and never regenerated.
- **Checkov Python check**: a Checkov resource check whose `scan_resource_conf` is Python of its own. The importer serializes its code (with the helpers it calls and the constants it reads) as a restricted-Python AST in a `checkov_python` clause (IR version 4); `tf_rule_ir::checkov_python` interprets it over the Checkov-shaped configuration with Python's semantics. An abstract value decides the run only when the code inspects it. Conformance: `bench/checkov/python_compare.py` against Checkov's runner over its own test fixtures.
- **Runner rendering**: what Checkov's runner does to a resource's configuration before resource checks see it, reproduced by `checkov::configuration`: string booleans become booleans, lists put their strings (sorted) last, a top-level string that evaluates to a list or dict (a heredoc JSON policy) becomes it, and the elements of list attributes are evaluated as Python literals. Graph policies see Checkov's vertex attributes instead, which are not rendered this way here.
- **Rule alias**: another ID of a rule (`RuleMeta::ALIASES`, `RuleInfo::aliases`). A seed rule aliases a bundled Checkov rule only once it has been shown to flag the same resources. The seed rule then replaces it in the catalog, and either ID selects it and `checkov:skip`s it. Listed by `oxtf rules` and `tfscan.rules()`.
- **Rule selection**: an explicit selection of IDs from the whole resolved rule catalog, the same in the CLI (`--rule`) and Python (`select=`). Unknown IDs are errors; an empty selection is valid and runs nothing.
- **Checkov pack**: a version-pinned export of compatible Checkov resource predicates and graph policies into native rule IR. Its manifest inventories translated and unsupported checks with reasons and source hashes. Execution uses configured abstract values; it requires no Checkov runtime. Original custom resource checks instead use the optional Python adapter. Usage and limits are in `docs/plans/RULE_ENGINES_PLAN.md`.
- **Resource dependency graph**: evaluated resource traversals retained separately from the bounded explanation chain, including local module outputs and instance keys. Connections are undirected for Checkov policies; literal equality never creates an edge. A graph is shared by all graph rules for one analysed root.
- **Scan request**: the one front door (`tf_scan::ScanRequest`): input (directories or a plan), catalog, selection, var files, installed-module data directory, threads. Every adapter (CLI, Python, tests) builds one; the result is a `ScanResult` plus the analysed model. Errors before rules run (bad path, bad rule file, bad policy, unknown ID) refuse the scan; a rule failing on a resource is a **rule error** on the result.
- **Overlay**: in-memory files that shadow the disk for one scan (`tf_scan::ScanRequest::overlay`, `--overlay PATH=FILE`, Python `overlay={path: text}`). Their text is read instead of the file's and they are listed in their directory whether or not it, or the file, exists. The file table is the one seam: everything that lists or reads source goes through it. This is how an unsaved buffer, stdin, or a proposed patch is scanned, and how a fix is verified by fingerprint without writing the checkout.
- **Installed module**: remote source resolved offline from the scanned root's Terraform module manifest. Resolution checks the static call path, ancestor sources, and installed versions. `data_dir` selects the data directory, relative to each root unless absolute. Parsed definitions remain shared separately. Missing or stale installations are coverage gaps; cache files are excluded from automatic edits. Installed finding identities use source, version, and package-relative file instead of cache location.
- **Fetched package**: a read-only, content-addressed snapshot created by the explicit `tf_scan::fetch(FetchRequest)` operation. Git commits or extracted-content SHA-256 revisions extend installed package identity. Fetch verifies cached snapshots before reuse; refresh resolves sources again and publishes a complete manifest atomically. Scans remain offline and use the existing installed-module resolver. Credentials are transport inputs, never package metadata.
- **Arena admission**: cumulative `arena_bytes` bounds parser chunk payload capacity and `ast_nodes` counts boxed values and arena-vector insertions. Cached modules, JSON/override construction, temporary template/default parsers, and Conftest HCL parsing share the scan input budget. Refusal is typed and sticky; partial ASTs are omitted, earlier errors survive, and incomplete scans cannot verify fixes. These counters exclude parser scratch and model/result storage; see `docs/LIMITS.md`.
- **Evaluator text admission**: scan-owned `text_bytes` admits literal copies, bounded string/template builders, builtin and contextual text, JSON text expansion, and primitive conversions. Refusal remains visible through `try`/`can` and cached defaults. It is a cumulative construction allowance; container, graph, report, Python, and worker/model admission remain separate work. See `docs/LIMITS.md`.
- **Expansion budget**: up to 64 instances per known count/collection and 16,384 resource plus child-module instances per root by default. Exceeding either bound is an explicit coverage gap; an omitted expansion never becomes a known empty collection. Concrete count keys are numeric throughout addresses and instance caches.
- **JSON variable file**: literal attributes loaded from `.tfvars.json` or an explicitly supplied `.json` file. Default HCL then JSON variable files precede both auto-file formats in lexical order, followed by explicit files in argument order. Original byte spans and sensitivity flow through the same evaluator as HCL variables.
- **JSON configuration**: `.tf.json` mapped to the shared AST using Terraform block schemas and field contexts. Property order and repeated block properties survive parsing. Templates and native type/reference expressions map their decoded byte locations back to the original JSON. Variable defaults and other literal-only fields do not interpolate.
- **Effective configuration**: ordinary HCL/JSON declarations composed with ordered override files before indexing and evaluation. Attributes replace by name; nested blocks replace by type, with special handling for lifecycle, locals, variables, providers, and Terraform settings. Arena nodes retain their source file through `compose::Origins`. A declaration header, its effective attributes, and nested bodies can originate in different files. Whole-file rules use the effective AST with those origins.
- **Rule IR**: the JSON envelope a rule file carries (`tf_rule_ir::RuleSpec`: name, metadata, message, clauses). A clause's condition is one of two things: an **expression** in the IR's own operators (`col`, `cmp`, `list_any`, ... — what the Python expression API writes), or a **foreign program** carried whole (`checkov_value`, `checkov_attribute`, `checkov_graph`, `checkov_python`) and run by its own evaluator. The envelope is shared; the evaluators are not, and the bundled catalog uses only the foreign kinds. `version` records which build wrote a document; every operator is read the same way whatever it says. Lowering the Checkov value and attribute checks onto the IR's own operators would let one evaluator serve the expression API and most of the catalog; that is an open option, not the current design.
- **Rule error**: a rule hook that returned an error for a resource (a Rego runtime failure, an uncaught interpreted Python exception, unsupported execution or exhausted budget, or a Python callback that raised). Recorded as `rule_errors` with the rule and resource; scan status is `failed` and the CLI exits 3. Ordinary errors allow other rules to continue. Exhausting shared `rule_steps` or cooperative `rego_time_ms` stops later hooks for that root, preserving earlier findings. Input admission is shared by the scan; exhaustion reports `coverage-storage` and cannot produce a complete scan. Backend scratch is owned by the root budget and released when it ends.
- **Scan status**: `complete`, `incomplete` (a reported coverage gap), or `failed` (a rule error or error diagnostic), independently of findings and certainty. CLI exit 3 for incomplete/failed analysis takes precedence over finding thresholds. Both scans must complete before a fix can be verified.
- **Sensitivity**: a presentation mark carried by value provenance, separate from the uncertainty lattice. Rules see actual values; records, source snippets, Arrow exports and fix diffs mask marked evidence. Explicit value accessors and raw fix text retain it. See `docs/FINDING_SCHEMA.md`.
- **Finding**: one rule failing on one attribute (or the whole) of one resource declaration — rule, file, local address (`aws_s3_bucket.this`, no module path or instance key) and deciding attribute. The unit an agent fixes and a backlog files.
- **Occurrence**: one judgement that is a finding: the declaration judged as an instance in a root. A module scanned as its own root, each example calling it, and each `for_each` instance give occurrences of one finding. A finding's certainty is its most certain occurrence's; its fields describe a representative occurrence (most certain, then shallowest module instance). The engine and the Python/Arrow APIs work per occurrence; the record and every CLI output group them (`tf_linter::record::group`).
- **Certainty**: `definite`, `conditional` or `indeterminate` (`tf_linter::Certainty`): how sure oxtf is that the configuration is insecure. Not severity: that is the rule's **level** (`low` to `critical`).
- **Finding record**: the resolved, versioned (`schema`, now 3), machine-readable form of a scan: a `rules` table and the grouped findings with their occurrences. Every output format is a projection of it (`docs/FINDING_SCHEMA.md`); NDJSON and SARIF are built from it alone (`tf_linter::formats`).
- **Fingerprint**: a finding's stable identity across scans, from rule, repository-relative file (outermost `.git` ancestor), local identity and attribute path; never from locations, module path, instance key, root, message or certainty. The same from every root and working directory, so verify-by-fingerprint works whether the fix was scanned as one module or the whole repository.
- **Fix hint**: the part of a finding record that says what a mechanical edit would do (resource, attribute, literal, site). Whether and where to apply it is the caller's judgement.
- **Projection**: the evaluated model rendered into the input shape a foreign policy family expects. Only Known values are projected; abstract values become absent and are listed.
- **Abstraction list**: for one projected resource instance, the attribute paths whose values were Unknown, Tainted or OneOf and so did not reach the foreign policy. It decides the certainty of any foreign finding on that resource.
- **Indeterminate**: the certainty of a foreign finding on a resource whose abstraction list holds only provider-computed values. Neither Definite nor Conditional; needs a human.

- **Builtin collection admission**: cumulative scan-owned `collection_bytes` reserves builtin vector capacity and logical map-entry payload before construction, including alternative argument rows, JSON decoding reservations, and cached builtin defaults. Expression/semantic/model containers have their own admission boundaries; graph/provenance, collection headers and B-tree overhead remain excluded. See `docs/LIMITS.md`.
