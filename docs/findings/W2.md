# W2 findings: provider schema codegen

Status: all five W2 checklist items done. Exit-criteria numbers are below. Open questions Q3, Q4 and Q5 are answered with measurements. Scope cuts are listed in their own section.

Inputs are the committed snapshots in `schemas/providers/` (Terraform 1.16.6): **hashicorp/aws 6.68.0** (1730 resources, 685 data sources), **hashicorp/azurerm 5.9.0** (1106 / 396) and **hashicorp/google 8.7.0** (1375 / 471). Mid-spike the Google target moved from 7.46.1 to 8.7.0. Every number in this file comes from 8.7.0, except the one "naive blob" figure that is labelled 7.46.1.

Machine: 4 vCPU Intel Xeon @ 2.80GHz, 15 GiB RAM, no swap, rustc 1.97.0. **Caveat:** the W1 agent was compiling in the same tree at the same time. Every timing was run at least 3 times and the minimum is reported. Load average is in the raw output where it was captured.

### Generator workflow

The generator is a manually run binary with committed output, not a `build.rs`.

```
cargo run -p tf_schema_codegen --release -- generate    # rewrite crates/tf_schema/src/generated
cargo run -p tf_schema_codegen --release -- check       # exit 1 if generated files are stale (also a test)
cargo run -p tf_schema_codegen --release -- diff OLD.json NEW.json
cargo run -p tf_schema_codegen --release -- coverage [--list]
cargo run -p tf_schema_codegen --release -- views-all aws OUT.rs [EXCLUDE,..]   # Q4 experiment only
```

**Why not `build.rs`?** A build script would parse 32 MB of JSON on every clean build of `tf_schema`. Build scripts compile in debug, and the generator takes **2.47 s in debug** versus **0.65 s in release** (min of 3; see appendix A6). It would also put serde_json, phf_codegen and toml into every downstream build graph. The committed output is checked for freshness by a test (`generated_files_are_fresh`), so a stale blob fails `cargo test`.

To survive a broken generated file, `tf_schema_codegen` depends on `tf_schema` with `default-features = false`. That drops the `embedded` feature, which is what pulls in `src/generated`. The generator therefore always builds, even when the generated code is stale or broken. The generated modules carry `#[rustfmt::skip]` so that `cargo fmt` cannot make them stale.

### IR format: postcard with interned names, decoded lazily

- **Per-schema record:** `SchemaBody { version, block: Block { attributes: Vec<Attribute>, block_types: Vec<NestedBlock>, deprecated } }`.
  - `Attribute { name, ty: CtyType, flags: u8 }`. The flags are required, optional, computed, sensitive, deprecated and write_only.
  - `NestedBlock { name, nesting: Single|Group|List|Set|Map, min_items, max_items (0 = unbounded), block }`.
  - `CtyType` covers `String|Number|Bool|Dynamic|List|Set|Map|Object(Vec<ObjectAttr{name,ty,optional}>)|Tuple|Nested(mode, Block)`.
  - `Nested` covers protocol-6 `nested_type`. None of the three providers uses it today (checked: 0 occurrences), but the IR keeps it lossless.
  - Members are sorted by name, so every lookup is a binary search.
  - Descriptions are **not** in the runtime blob. They only feed the doc comments on views.
- **Name interning.** Names were 4.3 MB of the naive blob: 264,725 member names, but only 25,601 distinct ones (Python count over the 7.46.1 snapshots). Each name is therefore serialized as a varint id into a symbol table sorted by frequency, so the commonest names cost 1 byte. The id is passed through a thread-local (`ir::sym`) so the serde derives stay plain. Effect, measured before the Google 8.7.0 switch: **5,316,964 B naive → 1,445,666 B blob + 494,436 B symbols = 1,940,102 B (-63%)**. With Google 8.7.0 the total is 1,453,065 + 499,872 = **1,952,937 B**.
- **Why postcard, not rkyv.** rkyv would make access zero-copy, but it needs an aligned `include_bytes!` and a second set of archived types. With postcard, the lazy decode of a typical schema costs tens of microseconds (measured below), and the decoded structs are plain Rust that W3 can hold as `&'static`. The added complexity would not pay for itself.
- **Lazy, per resource.** A phf map takes a name to an entry id. `ENTRIES[id]` holds the byte range. `CACHE[id]` is a `OnceLock<ResourceSchema>` decoded on first use and leaked for the life of the process (`&'static`). The symbol table is decoded once, on first lookup. Eager decoding of all 5,763 schemas takes 22.5 ms, which is too much to pay at startup for a scan that touches tens of resource types.

Every accessor is `#[inline]` and carries a doc comment with type, flags and (where the provider gives one) the first sentence of the description. `size_of::<AwsSecurityGroup<&Body>>() == size_of::<&Body>()` is asserted in `tests/schema.rs`. Helpers live on the `TypedView` trait, not as inherent methods, so they can never collide with a schema attribute called `node`. Keyword attribute names are emitted as raw identifiers (`r#type`); `self` and `super` get a `_` suffix.

**Findings W3 must handle:**

- `aws_security_group.ingress` and `.egress` are **attributes** of type `set(object(...))`, optional and computed. They are not nested blocks. Users write them as blocks, which Terraform's attributes-as-blocks mode accepts. `Attribute::accepts_block_syntax()` flags this case, and the view exposes both `ingress()` and `ingress_blocks()`.
- Across all three providers there are 0 `nested_type` attributes, 3,135 `single` nested blocks, 2,798 `set` and 77,850 `list`.
- `google_storage_bucket.uniform_bucket_level_access` is optional and computed. When it is absent, Terraform gets the server value, which is normally `false` but `true` under an org policy. The overlay says `false` and has a note explaining this.

### Defaults overlay

`defaults/aws.toml` has 17 entries and `defaults/google.toml` has 5, for 22 in total. The format is `[resource] attr = value` or `"block.attr" = { value = ..., note = "source" }`, and `[]` means `Empty`. The generator validates every entry against the schema: the resource must exist, the path must resolve, and the value must match the attribute's type (`[]` only on a collection or a block). An invalid entry aborts generation; this is tested in `defaults_are_validated_against_schema`.

The overlay covers every seed-rule need:

- `aws_db_instance`: `storage_encrypted` and `publicly_accessible`, plus deletion_protection, iam_database_authentication_enabled, auto_minor_version_upgrade, copy_tags_to_snapshot, performance_insights_enabled, skip_final_snapshot and monitoring_interval.
- `aws_s3_bucket_public_access_block`: all four booleans.
- `aws_security_group`: `ingress` and `egress` (Empty), and `revoke_rules_on_delete`.
- `aws_s3_bucket.force_destroy`.
- `google_storage_bucket`: `uniform_bucket_level_access`, `public_access_prevention`, `force_destroy`, `requester_pays` and `versioning.enabled`.

Each entry's note cites a docs phrase or source `Default:` at the provider tag, verified by hand. AzureRM was cut (see Scope cuts).

### Schema diff and rule coverage

`tf_schema_codegen diff OLD.json NEW.json`:

- Reports added and removed resources and data sources. Added ones are tagged `(no rule targets it)` against `rule_targets.txt`.
- Reports every changed attribute or block path, recursively with type and flags.
- **Exits 1** when an allowlisted view that exists in OLD loses its resource, or loses any of its `uses` paths, in NEW.

`coverage` prints, per provider and kind, how many types have rules. Today that is 9 aws resources, 1 aws data source and 1 google resource; everything else has none.

**How removed attributes break the build.** There are two layers:

1. `generate` refuses to run if an allowlist `uses` path is missing from the schema. The test `removed_attribute_used_by_view_fails_generation` drops `aws_db_instance.storage_encrypted` from a copy of the schema and gets: `allowlist: view aws_db_instance uses `storage_encrypted`, which does not exist in the schema`.
2. Every attribute gets an accessor whether or not it is in `uses`. So when an attribute disappears, its accessor disappears from the generated API, and any downstream rule that calls `.storage_encrypted()` stops compiling. The same test asserts that the regenerated source no longer contains `pub fn storage_encrypted(`. `diff` runs check 1 before regeneration. The test `diff_cli_reports_breakage_and_uncovered_resources` covers the exit code and output.

**Real-world demo, google 7.46.1 → 8.7.0** (`git show a9bf078:schemas/providers/google.json` against the current snapshot):

- `added: 57 removed: 22 changed paths: 746` (exit 0), broken down as:
  - 45 resources added and 16 removed (`google_notebooks_*`, `google_iap_brand`, `google_iap_client`, `google_beyondcorp_app_*`, `google_ml_engine_model`, `google_vertex_ai_schedule`).
  - 12 data sources added and 6 removed.
  - Within the 96 types present in both, 659 paths were added, 16 removed and 71 changed.
- All 57 additions are tagged "no rule targets it". `google_storage_bucket` has no changed paths.
- With a throwaway allowlist that uses `google_container_cluster.node_config.host_maintenance_policy` (removed in 8.x), `diff` exits 1 with `BREAKING: allowlist: view google_container_cluster uses `node_config.host_maintenance_policy`, which does not exist in the schema`.

## Q3. Schema IR cost: embed all three providers, or load at runtime?

**Answer: embed.** The cost of embedding all three providers is:

| | Value |
|---|---|
| Binary size, tiny bin linking `tf_schema` (stripped) | **3,517,272 B**, vs 344,848 B for the same bin without it: **+3,172,424 B (+3.0 MiB)** |
| Compressed (gzip -9 of the stripped binary) | 753,031 B vs 168,129 B: +585 KB |
| Startup | lazy, so the cost is paid on demand: ~1 ms on first lookup, then tens of µs per new schema type (3–4.6 ms worst case) |
| Compile time | +1.1–1.3 s per clean or incremental rebuild of the `tf_schema` crate. Downstream crates do not recompile it unless it changes |

The binary grows by about 3.0 MiB, of which the data is 1.95 MB. The rest is the index: `ENTRIES` holds 5,763 `&'static str` names, which costs relocations, and there are two phf tables. A scanner binary of a few MB, or a Python wheel, can carry this easily. Runtime loading would add a file-distribution and version-skew problem in exchange for saving 3 MB. Startup cost does not argue against embedding either, because decoding is lazy.

Possible later squeezes, not needed now:
- Drop the duplicated names in `ENTRIES`, since the phf keys already hold them.
- Compress the 7 giant AWS records (803,122 B, 55% of the blob).

## Q4. Typed views: every resource, or only an allowlist?

**Answer: allowlist.** Measurement setup: `views-all` generated views for all 1,730 AWS resources into a throwaway crate (`/tmp/claude-0/w2/bench`) that depends on `tf_schema` without `embedded`. That crate was compared with an identical crate holding the 11-type allowlist output. Builds are crate-only (deps prebuilt), min of 3.

| Variant | Lines | Source bytes | Clean build release | Clean build debug | Incremental (touch lib.rs) rel / debug | Peak rustc RSS | rlib size (release) |
|---|---|---|---|---|---|---|---|
| Allowlist (11 types) | 4,022 | 135 KB | **0.36 s** | 0.48 s | 0.44 s / 0.22 s | 116–118 MB | 761,828 B |
| All AWS except 6 giants (1,724 types) | 461,043 | 16.3 MB | **49.6 s** | 53.3 s | 40.9 s / 24.9 s | 2.28–2.43 GB | 108,142,586 B |
| All AWS (1,730 types) | 2,871,024 | 153.9 MB | **did not build:** rustc aborted (`memory allocation of 6586384 bytes failed`) after 100.7 s at 7.46 GB RSS under a 10 GB `ulimit -v` | – | – | >7.4 GB | – |

Notes:

- **Six resources make up 2.41M of the 2.87M lines**, because nested blocks get one view struct per nesting path: aws_wafv2_web_acl_rule 758,133 lines, aws_wafv2_web_acl 369,707, the three aws_quicksight_* at about 329k each, and aws_wafv2_rule_group 294,578. The median resource is 124 lines, p90 465, p99 2,618.
- Views are generic, so these costs are front-end cost (parsing, type checking and metadata) and are paid even if nothing instantiates them. The 108 MB rlib is metadata that every dependent crate also has to load.
- **Verdict:** generate views only for resources with rules. Even after excluding the pathological nesting cases, generating everything costs about 50 s per change and 2.3 GB of compiler memory. The allowlist costs under 0.5 s. Rules for un-allowlisted resources can still use the dynamic API (`lookup_resource(...).attribute(...)`). The "all-views" mode stays an experiment (the `views-all` subcommand), not a feature flag on `tf_schema`, so the default build cannot pick it up.

## Q5. How much of the defaults overlay can be derived automatically?

**Answer: 18 of the 22 hand-written overlay entries (82%) can be derived automatically. The derived set is large: about 1,900 AWS and 1,000 Google (resource, path) pairs. Its precision on a hand-checked sample is high (59 of 60 correct; see the sample breakdown in the appendix). It still cannot replace hand review**, because the security-relevant "absent" semantics often live only in docs, or in no machine-readable form at all.

Method: `scripts/extract_defaults.py` was run on terraform-provider-aws at tag **v6.68.0** and terraform-provider-google at tag **v8.7.0** (shallow git clones under `/tmp/claude-0/w2`, not committed). It uses two extraction methods:

- **docs:** argument bullets in `website/docs/r/*.html.markdown`, with continuation lines joined (the mmv1 style), matched against "Defaults to `x`", "Default is `x`", "Default: `x`", "(Optional, Default: x)" and "Default value is `X`". The path comes from the section heading (`### \`ingress\` Block`), or from a unique path in the schema that ends in that name.
- **source:** `Default:` in the Go schemas. This covers SDKv2 literals, framework `booldefault.StaticBool(x)` and similar, and `names.AttrX` constants resolved via `names/attr_consts_gen.go`.
  - The key path is recovered by brace-matching outward over string-masked source.
  - The resource is resolved from `@SDKResource`/`@FrameworkResource` annotations (aws) or `registry.Schema{Name: ..., Schema: ResourceX()}` registrations (google).

Every candidate is validated against the schema JSON: the path must exist and the literal must fit the attribute type. Counts below exclude `timeouts.*`.

| | AWS 6.68.0 | Google 8.7.0 |
|---|---|---|
| docs: candidates / validated | 3,291 / 3,162 (1,557 non-timeout pairs, 502 resources, 609 bool) | 3,530 / 2,890 (308 non-timeout pairs, 212 resources, 54 bool) |
| docs: rejected | 110 unresolved path, 19 type mismatch | 638 unresolved path, 2 type mismatch |
| source: candidates / validated | 1,681 / 1,033 (1,018 distinct pairs, 404 resources, 626 bool) | 1,006 / 899 (847 pairs, 302 resources, 288 bool) |
| source: rejected | 460 non-literal (enum constants, helper vars), 162 not attributable to a resource (shared helper files), 22 unresolved, 4 no key | 96 not attributable, 6 unresolved, 5 no key |
| overlap (in both) | 648 pairs: **641 agree, 7 disagree** | 155: **151 agree, 4 disagree** |
| docs only / source only / union | 909 / 370 / **1,927 pairs on 590 resources** (821 bool) | 153 / 692 / **1,000 pairs on 375 resources** (311 bool) |
| Context: optional bool attributes in resource schemas (excluding timeouts) | 1,810 | 1,711 |
| Recall of the hand overlay | docs 14/17, source 12/17, either **14/17** | docs 4/5, source 1/5, either **4/5** |
| Precision spot-check (random, seeded, verified by reading the line) | docs 19/20 (1 conditional: "Defaults to `TwentyFour_Hours` for periodic …"); source 20/20 | docs 10/10; source 10/10 |

Disagreements are almost all **unit errors in the docs extraction**:
- `timeout_milliseconds` docs 29 ("29 seconds") vs source 29000.
- firehose `block_size_bytes` 256 ("256 MiB") vs 268435456.
- `stickiness.cookie_duration` 1 ("1 day") vs 86400.
- codebuild `queued_timeout` 8 (hours) vs 480.
- google pubsub `message_retention_duration` "7" (days) vs "604800s".
- workstations timeouts.

There is also one docs parse bug: google `compute_router_peer.advertise_mode` came out as ", ". So **source wins on value precision, and docs win on coverage.**

What the extractors miss, and why the hand overlay remains:

- `aws_db_instance.storage_encrypted` has **no `Default:` in source** (`rds/instance.go:662`: `Optional: true, ForceNew: true`). Unset means null, and the AWS API default (unencrypted) applies. Only the docs say "The default is `false` if not specified". The same holds for `deletion_protection`. `iam_database_authentication_enabled` appears in neither.
- `google_storage_bucket.uniform_bucket_level_access` and `requester_pays` are found only by docs. `uniform_bucket_level_access` is optional and computed, so a `Default:` cannot exist for it.
- Semantic defaults are not expressible as `Default:` and are not phrased as "Defaults to" in docs. Examples: `aws_security_group.ingress`/`egress` absent means no rules (and Terraform deletes AWS's default egress rule), and `google_storage_bucket.versioning.enabled` with the block absent means off.

**Recommendation:** generate a draft overlay from docs ∪ source, preferring source on conflict. Commit it as a separate machine-generated file, validated by the same generator check. Keep `defaults/*.toml` as hand-reviewed overrides for the attributes rules actually depend on. Rules should only trust overlay entries that were reviewed by hand or came from source. A docs-only entry should not be trusted when a units word follows the number; there are 34 such numeric docs extractions in AWS.

## Scope cuts

| Cut | Why |
|---|---|
| `defaults/azurerm.toml` not written | No seed rule targets azurerm, so the overlay would have been unvalidated by any rule. The generator already loads `defaults/azurerm.toml` if it exists. |
| Derived defaults (Q5) not merged into the runtime overlay | The goal was to measure feasibility. Merging needs a review policy (see recommendation). The extraction JSONL lives only in `/tmp`; rerun the script to regenerate it. |
| Descriptions not in the runtime blob | They are only used for view doc comments. Keeping them would add MBs. |
| "All views" not shipped as a `tf_schema` feature | Measured in a throwaway crate instead, so the default build is unaffected (Q4 shows it is not viable anyway). The full 1,730-type build was capped at a 10 GB address space and aborted rather than risk an OOM that would kill the concurrent W1 build. |
| Typed-view accessors return untyped `Option<N::Value>` | Value typing is the evaluator's job (W3). Schema type, flags and defaults are available through `lookup_resource`. |
| Google source attribution only via `registry.Schema` registration | 96 `Default:` hits in helper files stay unattributed. Good enough to measure Q5. |

## Known gaps

- The `diff` breakage check covers only the allowlist `uses` paths. Accessors used by downstream code but not listed in `uses` fail at compile time, not at `diff` time.
- `ResourceNode::blocks` must also yield blocks written for attributes-as-blocks attributes (e.g. `ingress { }`) for `*_blocks()` accessors to work. W3 implements this.
- The overlay value types are scalar or `Empty`. Defaults that are lists, maps or objects are not representable yet. None are needed by the seed rules.
