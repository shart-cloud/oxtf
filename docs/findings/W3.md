## Crates

```
crates/tf_eval/        values, provenance, evaluator, functions, four-valued truth (no module or schema knowledge)
  src/value.rs         the lattice (Value = Kind + Prov), JSON conversion, Display
  src/prov.rs          provenance chains (Step, Prov)
  src/eval.rs          Evaluator over a Resolver trait; Scope (lexical frames); templates; lifting over OneOf

  tests/eval.rs
crates/tf_semantic/    modules, symbols, schema-aware evaluation, owned model
  src/source.rs        FileTable (thread-safe, append-only; stable FileIds across a scan)
  src/module.rs        ModuleDef: parsed directory, symbol table, reference edges
  src/analyze.rs       instance tree, Resolver impl, count/for_each/dynamic, body evaluation
  src/model.rs         owned output model: Analysis / Module / Resource / Body / Attr
  tests/exit.rs        W3 exit test and semantic tests
  examples/q6_eval_depth.rs, examples/dump.rs
```

**Why two crates.** `tf_eval` only knows HCL expressions and values; references whose root is not lexically bound go through a `Resolver` trait that `tf_semantic` implements per module instance. This keeps the lattice, functions and evaluator testable without module loading or schemas (`tf_eval/tests/eval.rs` parses a single expression and evaluates it with `NoResolver`), and lets a later plan-JSON front end (W5) or the Python bindings build `Known` values with provenance without pulling in the semantic layer. `tf_semantic` depends on `tf_eval`, `tf_schema`, `tf_parser`.

Sizes (`wc -l`, including doc comments and unit tests): `tf_eval` 3,072 lines (functions.rs 1,196, eval.rs 808, value.rs 604, prov.rs 229, truth.rs 210), `tf_semantic` 2,620 lines (analyze.rs 1,652, module.rs 563, model.rs 238, source.rs 143).

## Value lattice

```text
Value { kind: Kind, prov: Prov }                              32 bytes (size test)
Kind  = Known(Known)            concrete; containers hold abstract children
      | Unknown(Arc<Origin>)    not knowable statically; the origin says why
      | Tainted(Arc<Taint>)     depends on an unconstrained input
      | OneOf(Arc<OneOf>)       one of several values (+ `tainted` flag)
Known = Null | Bool | Number(f64) | String(Arc<str>)
      | List(Arc<Vec<Value>>)   tuple / list / set
      | Object(Arc<BTreeMap<Arc<str>, Value>>)   object / map
      | Json(Arc<Value>)        `jsonencode(v)`: a string whose text is the JSON of v, kept structured
Origin = Computed { resource, key, attr }   computed by provider (resource address kept for joins)
       | RemoteModule { module, output }     registry / git / http module output
       | UnsupportedFunction(name)
       | Error(msg)                           evaluation error; `try` / `can` distinguish it
       | Other(msg)                           count.index not expanded, terraform.workspace, ...
```

Children of a Known container are themselves abstract, so `["10.0.0.0/8", var.x]` is a Known list whose second element may be Tainted, and per-element provenance survives.

**Tainted, precisely.** A value is `Tainted` iff it is the value of an *unconstrained input* (a root-module variable with no default and no tfvars / var-file value, or a child-module variable not set by its `module` block and without default), or the result of an operation that needed the concrete value of one. Rules:

1. Structure-only operations keep taint local: `[var.x, "a"]` is a Known list with one Tainted element; `length([var.x])` is Known 1; `jsonencode({a = var.x})` keeps the Tainted field inside a `Json` value.
2. An operation that needs the concrete value returns Tainted: `"${var.prefix}-x"`, `var.cidrs[0]`, `lower(var.x)`.
3. When an operation combines inputs that are not Known, precedence is Error > Unknown > Tainted. `"${var.x}-${aws_vpc.v.id}"` is Unknown: the value is not chosen by whoever sets the variable alone. (Functions that inspect arguments one at a time return the first non-Known argument they hit; this is an approximation of the precedence.)
4. A conditional whose condition is Tainted yields `OneOf([then, else], tainted = true)`; with an Unknown condition the flag is false.
5. `dynamic` / `for_each` over a Tainted collection yields one abstract instance whose iterator is Tainted; the instance itself is `OneOf([element, null], tainted = true)` ("may be absent"), and a resource's `existence` becomes `Tainted`.
6. `lookup(known_map, tainted_key, default)` is `OneOf(values ∪ {default}, tainted = true)`; on an empty map it is the default.

W4 maps this to severity through `tf_eval::truth`: a predicate over a value is `True` (definite), `Tainted` (conditional: holds for some value of an unconstrained input), `Unknown` (depends on apply-time data: no finding) or `False`. On a `OneOf` a predicate is True if it holds for every alternative; if it holds for some, it is Tainted when the OneOf is tainted and Unknown otherwise.

## Provenance

`Prov` is an `Arc`-shared cons list of `Step { kind, at: FileSpan, label: Arc<str>, resource: Option<Arc<str>> }`, newest first (8 bytes per value; `size_of::<Prov>() == 8` is asserted). Push is O(1) and shares the tail; a step at the same place as the head is not repeated; chains are capped at 48 steps.

Steps are pushed at definition boundaries, not at every use site:

| event | step kind | label example |
|---|---|---|
| tfvars / var-file binding | `Tfvars` | `terraform.tfvars: admin_cidr = "0.0.0.0/0"` (attribute span) |
| value passes through a `variable` | `Variable` | `variable admin_cidr` (span: block header) |
| variable default used | `VariableDefault` | `variable ingress_rules default` |
| module argument → child variable | `ModuleArgument` | `module.sg argument cidr` |
| `locals` entry | `Local` | `local.ssh_sources` |
| child module `output` | `Output` | `module.x output name` |
| resource / data / nested-block attribute | `Attribute` (+ `resource` address) | `aws_security_group.admin ingress.cidr_blocks` |
| `for_each` / `dynamic` collection | `Iteration` | `aws_security_group.dyn dynamic "ingress" for_each` |
| defaults overlay (W4, `Resource::value_or_default`) | `Default` | `... storage_encrypted not set: provider default false (defaults overlay; ...)` |

Nested values carry only their own steps. Projecting an element out of a container (`x.a`, `x[i]`, `for`, `dynamic`, splat) joins chains: `element.prov.then(&container.prov)` (element history first, then the container's history after the element was placed in it; duplicates skipped). This is why the exit test's `"0.0.0.0/0"` carries tfvars → variable (its own steps) followed by local → attribute (the list's steps). Primitive results of functions inherit the joined provenance of their arguments (`lower(var.x)` still points at `var.x`).

The `resource` field of attribute steps is what W4's S3 join uses for `bucket = aws_s3_bucket.data.bucket` (a Known string whose chain passes through `aws_s3_bucket.data bucket`); `.id` references are matched through `Origin::Computed { resource }`.

## Semantic layer

- **Assembly.** `load_module(dir)` parses every `*.tf` file (sorted) into the scan's arena and indexes declarations. Root variables bind from `terraform.tfvars`, then `*.auto.tfvars` (lexical order), then `--var-file`s; later wins. Tfvars expressions are evaluated with no resolver (references are errors, as in Terraform).
- **Instance tree.** The root module is instance 0; each `module` block with a local source (`./`, `../`) is instantiated (after evaluating its `count` / `for_each` in the parent) with address `module.name` or `module.name["key"]`, recursively, with cycle and depth (10) guards. Remote sources (anything else) are not instantiated; `module.x.out` evaluates to `Unknown { RemoteModule }`.
- **Laziness.** Variables, locals, outputs, resource attributes and resource instance expansions are memoised per instance (`RefCell<HashMap<_, Slot::{Busy, Done}>>`); re-entering a `Busy` slot is a cycle and yields an error value. A depth counter (400) bounds recursion.
- **Type constraints.** Variable values are converted by their `type`: primitive conversions (string ↔ bool / number), recursively through `list`/`set`/`map`/`tuple`/`object`, and `optional(T, default)` attributes (absent or null → default or null). `nullable = false` with a null argument uses the default. Q6 showed why this matters: before it, 208 security-relevant evaluations were Unknown because `each.value.redirect != null` failed on objects missing optional attributes; after it, 2.
- **count / for_each.** `count` Known 0 → no instances; 1 → one instance with `count.index = 0`; N > 1 → one representative instance with `count.index` Unknown; Tainted / Unknown / OneOf → one abstract instance whose `existence` is Tainted / Unknown. `for_each` over a Known map or set (≤ 64 elements) expands to keyed instances (`aws_s3_bucket.b["a"]`); larger collections and non-Known ones become one abstract instance with `each` Unknown / Tainted.
- **References to resources.** `type.name[key].attr`: an attribute set in configuration is evaluated in the chosen instance's scope (memoised) and gets an `Attribute` step with the resource address; a config `null` on a computed attribute, a computed-only attribute, or an optional+computed attribute that is not set → `Unknown { Computed { resource, key, attr } }`; an optional non-computed unset attribute → the defaults-overlay value or null. `data.aws_iam_policy_document.x.json` is rendered from its `statement` blocks (added in W4, see W4.md).

### Schema use (tf_schema)

- **Blocks vs attributes.** When evaluating a body, a block whose name is a schema *nested block* stays a block (`model::Block`); a block whose name is a schema *attribute* (Terraform's attributes-as-blocks, e.g. `aws_security_group.ingress` / `egress`, `set(object)`) becomes an element (an object) of that attribute's list value, `Attr { from_blocks: true }`. Unknown resource types (no schema) keep all blocks as blocks.
- **Computed.** `Attribute::is_computed()` drives the Unknown-with-address rule above.
- **AWS 6.x strict booleans.** For AWS resources, a Known string `"true"` / `"false"` assigned to a bool-typed attribute (top level or nested block) produces a `strict-bool` warning diagnostic and is coerced to the bool, so rules see the value Terraform would send. Decision: diagnose and coerce rather than fail, because Terraform core itself converts the string; the diagnostic flags the style issue. On the corpus this fired 0 times.

## Evaluator

Covers every `Expression` variant: literals, templates (with `%{if}` / `%{for}` directives and `~` strip markers applied as in Go HCL: `${~` trims the preceding literal, `~}` the following one, directive bodies included), heredocs (`<<-` already dedented by the parser), traversals (attribute, index, legacy index, `[*]` / `.*` splats), function calls (with `...` expansion), tuples, objects (expression keys), `for` (list / object / grouping `...` / `if`), conditionals, unary and binary operators (Kleene short-circuit for `&&` / `||`), parentheses. A template that is a single interpolation yields the value itself, type preserved. Operations over `OneOf` operands are lifted (cartesian product up to 16 alternatives).

**Functions (77 + `try`, `can`).** abs, alltrue, anytrue, base64decode, base64encode, basename, ceil, chomp, chunklist, cidrhost, cidrnetmask, cidrsubnet, cidrsubnets, coalesce, coalescelist, compact, concat, contains, dirname, distinct, element, endswith, flatten, floor, format, formatlist, indent, index, join, jsondecode, jsonencode, keys, length, log, lookup, lower, matchkeys, max, merge, min, nonsensitive, one, parseint, pow, range, replace (non-regex), reverse, sensitive, setintersection, setproduct, setsubtract, setunion, signum, slice, sort, split, startswith, strcontains, strrev, substr, sum, title, tobool, tolist, tomap, tonumber, toset, tostring, transpose, trim, trimprefix, trimspace, trimsuffix, upper, urlencode, values, zipmap; `try` / `can` are lazy (in the evaluator; `can` on a partially unknown value returns true: approximation). ### What the long tail is

- **Forms.** 38% of security-relevant expressions are literal-only; resource references (22.4%), indexing (19.4%), `var` (15.8%), `each` (10.6%), function calls (9.5%), templates (7.7%), locals (6.9%) follow. `for` expressions, splats and operators are each under 1% *at the attribute*, but they matter one level up: `for_each` and `dynamic` collections are built with `for` and `merge`, which is where the evaluator's work actually goes.
- **Functions.** Two functions, `try` (30.1%) and `lookup` (24.3%), are over half of all call sites; the top 10 are 81.0%. The unimplemented remainder (101 call sites, 0.9%) is `regex`/`regexall`, file readers and nondeterministic functions (`timestamp`, `uuid`); none is called directly in a security-relevant attribute in this corpus, and only 3 security-relevant evaluations hit an unsupported operation (`replace` with a regex pattern).
- **Where Unknown comes from.** Not from missing functions (3 evaluations of 4,353 are `unsupported function`, all `replace` with a regex pattern). It comes from values only the provider knows (13.3% `computed by provider`, mostly resource ids/ARNs, plus data-source attributes such as `.partition` 3.1%, `.arn` 1.3%) and from **remote module outputs** (2.5%, e.g. `module.vpc.private_subnets_cidr_blocks` from the registry VPC module; that module's source is in the corpus, but registry sources are opaque by design). The next evaluator investments are therefore: (1) more deterministic data sources (as done for `aws_iam_policy_document`, which moved 254 evaluations from Unknown to Known/partial; `aws_partition` / `aws_caller_identity` could be treated as Tainted-like "account inputs"), (2) optional resolution of registry modules from a local cache, (3) per-instance `count` expansion (47 evaluations are `count.index` not expanded).
- **Fixes the measurement drove** (each rerun recorded in the appendix): `optional()` type defaults (dynamic-iterator unknowns 208 → 14; `object has no attribute` errors gone), then `nullable = false` and "config null on a computed attribute is computed" (dynamic-iterator unknowns 14 → 2, `each` unknowns 440 → 280), then `setproduct` / `basename` / `base64*` (`each` unknowns 280 → 0), then `aws_iam_policy_document` rendering (data-source `.json` unknowns 254 → 0). Known evaluations went from 60.3% to 77.3% over these four steps.

## Scope cuts and known gaps

- `.tf.json` files and `override.tf` / `*_override.tf` merging are not handled (override files are read as ordinary files). `terraform.tfvars.json` is not read.
- `count` with N > 1 is not expanded per instance (one representative instance with `count.index` Unknown). `for_each` expands up to 64 keys.
- Module `for_each` / `count` expand like resources; references to a whole module instance map (`module.x` without key when it has several instances) give a `OneOf` over instances' outputs.
- `regex`, `regexall`, `file`, `templatefile`, hashes, time functions are not implemented (Unknown with origin).
- References to nested blocks of another resource (`aws_x.y.block[0].attr`) are Unknown; only top-level attributes are resolved.
- `self`, `terraform.workspace` are Unknown; `path.module` is relative to the root module directory, `path.root` / `path.cwd` are `.`.
- Type constraints: `any`, nested `tuple`/`object` defaults inside `optional` beyond literals (only literal defaults are evaluated).
- Provider-defined functions (`provider::aws::...`) are Unknown.
- Lifting precedence (Error > Unknown > Tainted) is exact for operators and `lift2`; functions that scan arguments in order return the first non-Known argument.
- No changes were needed in tf_ast / tf_parser / tf_schema. (tf_schema gained providers and nested attributes concurrently from W2; tf_semantic builds and passes against it.)
