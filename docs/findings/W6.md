### Python API

```python
import tfscan
from tfscan import col, element, rule

res = tfscan.scan("path", recursive=True, var_files=[...], builtin=True | False | ["aws-sg-open-ssh"],
                  rules=[expr_rule, callback_rule, compiled_rule], threads=None)   # GIL released
res.findings          # list[Finding]: rule level severity address resource_type module message root file line column
                      #                provenance (list of {kind,label,file,line,column,resource}), render(), to_json()
res.findings_arrow()  # pyarrow.Table (also res.to_arrow(); pa.table(res) works through __arrow_c_stream__)
res.resources         # Sequence[Resource]; .to_arrow(), .of_type(t)
res.stats, res.diagnostics, res.to_json(), res.callback_calls
r = res.resources[0]; r.type, r.address, r["ingress"], r.get(n), r.get_or_default(n), r.to_json()
v = r["ingress"]      # Value: kind ∈ known|unknown|tainted|one_of, items(), get(), alternatives, variable, origin,
                      #        provenance, py(), to_json(), to_str(), as_number(), as_bool()
tfscan.analyze(path)  # model only (no rules)
doc = tfscan.parse(src)   # arena AST handles (Q7): doc.blocks(), node.kind/span/text/labels/attributes()/value/literal()

open_ssh = (rule("py-sg-open-ssh", level="high")
    .on("aws_security_group").for_each("ingress")
    .where_((col("cidr_blocks").list.any(element().is_in(["0.0.0.0/0", "::/0"])) | ...) & ...)
    .on("aws_vpc_security_group_ingress_rule").where_(...)       # more clauses, or-ed per resource
    .message("ingress allows SSH (port 22) from {witness|the internet}"))
open_ssh.to_json(); open_ssh.compile(); tfscan.save_rules("rules.json", [open_ssh])

@tfscan.callback_rule("py-cb", resource_types=["aws_db_instance"], level="high")
def check(resource) -> str | tfscan.Report | list | None: ...
```

Expression operators: `== != < <= > >=`, `& | ~` (Python `and`/`or`/`if` on an `Expr` raise, as in polars), `.is_in`, `.is_null`, `.is_not_null`, `.is_known`, `.list.contains / .any / .all`, `col("a.b")` / `col("a", "0", "b")` paths (numeric segments index lists), `col(..., default=True)` (defaults overlay), `element()`, `lit()`, `all_of`/`any_of`. Message placeholders: `{address} {type} {name} {rule} {witness} {witness|fallback}`.

The full seed rule 1 in both styles is `python/tfscan/examples/sg_open_ssh.py`: the expression version is lines 24–62 (39 lines, including the shared constants), the callback version lines 64–140 (77 lines; it has to carry the lattice itself through `tfscan.truth`).

### Rule IR schema (`tf_rule_ir`, version 1)

```
RuleSpec  { version: 1, name, description = "", level = "medium" (low|medium|high|critical),
            category = "network" (network|storage|iam|encryption), message, clauses: [Clause] }
Clause    { resource_types: [str], for_each?: Expr, condition: Expr }
Expr (tagged by "op"):
  col        { path: [str], default?: bool }   attribute / field access (missing → null; numeric segment = index)
  element    {}                                the current list element
  lit        { value: null|bool|number|string }
  cmp        { cmp: eq|ne|lt|le|gt|ge, left, right }
  is_in      { expr, values: [scalar] }
  list_contains { list, value }   list_any { list, pred }   list_all { list, pred }
  and { args }   or { args }   not { arg }   is_null { expr }   is_known { expr }
```

A rules file is one rule, a list of rules, or `{"rules": [...]}`. Unknown fields and ops are rejected (`deny_unknown_fields`); `compile` also checks the version, level, category, message placeholders, non-empty clauses and that literals are scalars. Example (one of the three clauses of seed rule 1; the full rule is `crates/tfscan_py/rules/sg_open_ssh.json`, 9,184 bytes pretty-printed, 66 expression nodes):

```json
{"version": 1, "name": "py-sg-open-ssh", "level": "high", "category": "network",
 "description": "Security group ingress allows SSH (port 22) from 0.0.0.0/0 or ::/0",
 "message": "ingress allows SSH (port 22) from {witness|the internet}",
 "clauses": [
  {"resource_types": ["aws_vpc_security_group_ingress_rule"], "condition": {"op": "and", "args": [
    {"op": "or", "args": [
      {"op": "is_in", "expr": {"op": "col", "path": ["cidr_ipv4"]}, "values": ["0.0.0.0/0", "::/0"]},
      {"op": "is_in", "expr": {"op": "col", "path": ["cidr_ipv6"]}, "values": ["0.0.0.0/0", "::/0"]}]},
    {"op": "or", "args": [
      {"op": "is_in", "expr": {"op": "col", "path": ["ip_protocol"]}, "values": ["-1", "all"]},
      {"op": "and", "args": [
        {"op": "is_in", "expr": {"op": "col", "path": ["ip_protocol"]}, "values": ["tcp", "6", "TCP"]},
        {"op": "cmp", "cmp": "le", "left": {"op": "col", "path": ["from_port"]}, "right": {"op": "lit", "value": 22}},
        {"op": "cmp", "cmp": "ge", "left": {"op": "col", "path": ["to_port"]}, "right": {"op": "lit", "value": 22}}]}]}]}}
 ]}
```

**Semantics (identical to W4).** Predicates are evaluated with `tf_eval::truth`: comparisons are `truth::map` over both operands (lifted over `OneOf`), `is_in` / `is_null` are `truth::test`, `list_*` are `truth::exists`, `and`/`or` are left folds of `Verdict::and`/`or`, `not` is `Truth::negate` (Tainted and Unknown stay as they are), and a clause's `for_each` is `exists(list, |e| map(e, condition))`. The engine's `RuleContext::report` turns `True` into a definite finding, `Tainted` into a conditional one, and `Unknown`/`False` into nothing (including the existence downgrade and the "depends on unconstrained variable var.x" suffix). The witness is the non-literal side of a comparison, so provenance and primary location come out the same as in the hand-written rules. Equality uses Terraform's conversions: numbers compare numerically (strings are parsed), bools as bools, strings by their trimmed string form. That matches the seed rules' `str_in` / `as_number` / `as_bool`.

## Q7: arena lifetime across PyO3

**Answer: the `self_cell` + `Arc` + node-id pattern works and costs nothing per access. It does need two `unsafe impl`s and closure-only access, and for this project it is not the model Python users need: the evaluated model is already owned.** Evidence:

1. **What the semantic model already decided.** W3 drops the arena after analysis and produces an owned, `Send + Sync` model (`tf_semantic::Analysis`; values are `Arc`-shared `tf_eval::Value`s). So the scan API binds that model directly. The `ScanData` (findings, `FileTable`, analyses) sits behind one `Arc`. `Finding` holds `(Arc, index)` and `Resource` holds `(Arc, (analysis, module, resource))`. `Value` holds a cloned `tf_eval::Value`, which is a refcount bump. This needed no lifetimes, no `unsafe`, and no copies at scan time. The single exception is callback rules, which get an `Arc<Resource>` clone because the engine only borrows the analysis during the scan.
2. **The arena AST prototype** (`src/ast.rs`, 411 lines including the Python methods and the micro-benchmark): `OwnedParse = self_cell!(owner: {Allocator, String}, dependent: Parsed<'a> { nodes: Vec<AstKind<'a>>, parent, end, errors })`. Python's `Document` and `Node` hold `Arc<SharedParse>` plus a `u32` pre-order id, and children are walked through subtree-end indices. Everything compiles and passes `test_ast.py`: navigation, literals, recovery on broken input, and nodes keeping the document alive after the `Document` is gone.
3. **Lifetime contortion: invariance.** `tf_allocator::Box<'a, T>` wraps `&'a mut T`, so `Block<'a>` is invariant in `'a`. With `#[covariant]` the build fails ("lifetime may not live long enough", [A7](#a7-q7-compiler-evidence)). With `#[not_covariant]`, self_cell offers no `borrow_dependent()`. Every accessor is a `with_dependent(|owner, parsed| …)` closure that has to copy its answer out; `ast.rs` has 21 occurrences of `with_dependent` / `.with(`. That is fine for Python, which copies into `PyString` / `int` anyway. It does prevent handing out `&'a` views, so Rust code sharing the handle type is limited too.
4. **Thread-safety contortion: two `unsafe impl`s.** The arena is `!Sync`: `bumpalo::Bump` keeps its chunk list in `Cell`s, and arena `Vec`s hold `&Bump` plus `NonNull` pointers. Without `unsafe impl Send/Sync for SharedParse`, `#[pyclass]` refuses the type, because PyO3 0.29 requires `Sync` unless the class is `unsendable` ([A7](#a7-q7-compiler-evidence): E0277 on `Cell<NonNull<bumpalo::ChunkFooter>>`, `NonNull<BodyItem>`, …). `py.detach(|| parse(..))` also needs the result to be `Send`. The SAFETY argument holds: nothing allocates after construction, only shared references escape, and `allocated_bytes()` only reads. But it is an argument about bumpalo internals, and it would have to be re-checked if the AST ever gained a mutation API or if Python ran free-threaded. The owned model needed 0 `unsafe`.
5. **Per-access overhead** (`bench.py`; Python-side numbers are min of 5 × 200k calls, Rust loop is min of 5 × 20M accesses):

   | access | run 1 (ns) | run 2 (ns) |
   |---|---|---|
   | arena AST `Node.span` (`with_dependent` + node table) | 87 | 94 |
   | arena AST `Node.kind` | 117 | 120 |
   | arena AST `Node.block_type` | 106 | 99 |
   | owned model `Resource.type` (`Arc` + 3 indices) | 91 | 79 |
   | owned model `Finding.address` | 82 | 79 |
   | owned model `Value.kind` | 135 | 78 |
   | baseline: Python attribute / dict lookup | 57 / 75 | 31 / 41 |
   | Rust only: `with_dependent` + `AstKind::span` | 1.91 | 1.88 |
   | Rust only: owned `Vec<(u32,u32)>` index | 1.85 | 1.82 |

   The cell costs nothing measurable inside Rust (1.88–1.91 vs 1.82–1.85 ns). From Python, every handle access costs 80–120 ns, dominated by the PyO3 call itself and the same for arena and owned handles. That is 2–3× a plain Python attribute.
6. **Memory and granularity.** Parsing the whole corpus through the binding (2,171 files, 6,690,116 bytes, 635,378 nodes) takes 61.3–61.9 ms (min), about 108–109 MB/s, with a 40,919,232-byte arena (6.1 bytes per source byte, because each file gets its own `Allocator` with chunk slack). Creating a `Node` handle for every node takes 45.0–53.6 ms, close to the parse time itself. The whole arena stays alive while any single `Node` is alive.

**Conclusion.** For a read-only syntax API (linters on raw HCL, formatting checks, editor tooling) the pattern is usable: about 400 lines, constant-time access, no measurable Rust overhead. It does not force an owned export. Its costs are `#[not_covariant]` closures plus two `unsafe impl`s whose soundness depends on bumpalo internals. For security rules, which need evaluated values, the owned model is the right boundary and is what `tfscan.scan` exposes. A real build should keep the arena internal to parsing and analysis and expose only the owned model, plus perhaps the prototype's read-only `parse()` for syntax tooling.

## Q8: rule portability

**Answer: yes.** A Python expression rule serialises to the JSON rule IR, and the Rust CLI runs it with no Python runtime. The findings are identical, provenance chains included.

- `tfscan.save_rules("rules.json", [EXPR_RULE])` writes `{"rules": [...]}`. The rule inside equals the committed `crates/tfscan_py/rules/sg_open_ssh.json`.
- `oxtf scan --rule-file rules.json [--rule py-sg-open-ssh]` is the CLI change: it adds `--rule-file FILE` (repeatable), loads the rules with `tf_rule_ir::load_rules_file` and compiles them with `tf_rule_ir::compile`, and adds them to the built-in rules. `--rule` filters across both. A bad file exits with code 2 and a serde error. `ldd target/release/oxtf` lists only libgcc_s, libm and libc, and the runs use `env -i` (no `PYTHONHOME`, `PATH` or venv).
- `scripts/q8_compare.py` compares the CLI's `--format json` output with the same rule run from Python. The key is (rule, address, root, severity, message, primary file:line, and every provenance step's kind, label, file and line). Raw output: [A5](#a5-q8-rule-portability).

| scope | Python findings | CLI findings | identical |
|---|---|---|---|
| `fixtures/rules` (recursive) | 7 | 7 | True |
| `corpus/repos` (recursive) | 0 | 0 | True |
| generated seed 1 (400 roots) | 577 | 577 | True |
| generated seed 42 (3,000 roots) | 4,309 | 4,309 | True |

Also covered by `crates/tf_cli/tests/cli.rs::scan_rule_file` (IR rule == built-in on the conditional fixture, exit 2 on a missing file) and by the Rust test `tf_rule_ir/tests/sg_ssh_check.rs`.

**What does not port:**

- **Callback rules** are Python functions. `save_rules` raises `TypeError: CallbackRule('py-cb-sg-open-ssh', [...]) is not an expression rule; only tfscan.rule(...) rules serialize to the rule IR`.
- **Anything outside IR v1's operators.** For example `{"op": "regex_match"}` is rejected by the CLI with "unknown variant `regex_match`, expected one of `col`, `element`, …" and exit code 2. Rules that need cross-resource joins or JSON-document traversal are in the same position (see gaps).
- **Version mismatches.** The IR carries `"version": 1`, and readers reject other versions (pytest `test_validation_in_rust`).

## Arrow export

**Choice: build the columns in Rust with arrow-rs 60 (`arrow-array`, `arrow-schema`; `default-features = false`, `ffi`) and hand them over through the Arrow PyCapsule interface.** `ArrowStream.__arrow_c_stream__` returns an `ArrowArrayStream` capsule named `arrow_array_stream`; it is created with `PyCapsule::new_with_value` and needs no unsafe code. `tfscan` turns it into a table with `pa.RecordBatchReader.from_stream`, and `pa.table(res)` also works directly. I chose this over `pyo3-arrow` 0.19 because that would have added a second wrapper dependency (with `chrono-tz` etc.) for about 40 lines of glue. I chose it over Python lists plus `pyarrow.table` because of four properties:

1. no Python object is created per cell;
2. batches are built with the GIL released;
3. `provenance` becomes a native `list<struct<kind, label, file, line, column>>`;
4. the result is consumer-agnostic (polars, duckdb and others accept `__arrow_c_stream__`), with `pyarrow` only an optional extra.

**Schemas** (from the demo, [A2](#a2-fresh-venv-install-and-demo), and `test_arrow.py`):

- findings: `rule, level, severity, address, resource_type, module, message, root, file: string not null; line, column: uint32 not null; provenance: list<item: struct<kind, label, file: string not null, line, column: uint32 not null>>`.
- resources: `root, module, address, base_address, mode, type, name: string not null; key: string (nullable); existence, file: string not null; line, column: uint32 not null; attributes: string not null` (JSON). Abstract values are explicit in the JSON: `{"$unknown": origin}`, `{"$tainted": "var.x"}`, `{"$one_of": [...], "tainted": b}`, `{"$jsonencode": ...}`.

**Cost.**

- *Runtime, measured* on corpus resources (5,227 rows; min / median):

  | step | time (ms) |
  |---|---|
  | `resources.to_arrow()`, run 1 | 70.0 / 70.6 |
  | `resources.to_arrow()`, run 2 | 46.3 / 46.9 |
  | Python handles → lists → `pyarrow.table`, run 1 | 65.0 / 98.8 |
  | Python handles → lists → `pyarrow.table`, run 2 | 61.5 / 90.9 |
  | building the RecordBatch in Rust (breakdown) | 44.0 / 45.5 and 44.4 / 71.5 |
  | pyarrow import of the C stream | 0.0–0.1 |
  | attributes JSON alone via handles | 39.8–41.0 |
  | 11 scalar columns via handles | 12.9 / 13.2 and 12.9 / 16.4 |

  So the Arrow path is about the same as Python lists at the minimum and steadier at the median. Both are dominated by serialising every resource's attributes to JSON (`serde_json::Value` then `to_string`). The Arrow handoff itself is free.
- *Build and dependencies.* arrow-array pulls in 26 crates, including chrono, half, num-* and a syn proc-macro chain, out of 106 crates in the `tfscan_py` dependency graph (pyo3 brings 11). The stripped `_tfscan.abi3.so` is 6,398,480 B and the wheel 1,943,433 B. I did not build a variant without arrow, so the binary-size share of arrow is not measured.

## Generated `.pyi` stubs

`cargo run -p tfscan_stubgen` reads the W2 typed-view allowlist (`crates/tf_schema_codegen/allowlist.toml`, read only, not edited). For each entry it walks the schema through the `tf_schema` runtime API (`lookup` → `Block` attributes, nested blocks, `CtyType`, nested attributes) and writes two files:

- `python/tfscan/schema.pyi` (2,106 lines). It contains:
  - a `ResourceType` literal;
  - a `Scope` literal covering resource types and `type.attr[.attr]` paths into nested blocks and object elements;
  - one `…Attr = Literal[...]` alias per scope;
  - one `TypedDict` per scope, with cty types mapped (string → `str`, number → `float`, list/set → `list`, map → `dict[str, …]`, object / nested block → `TypedDict`; deeper than 3 levels → `dict[str, Any]`);
  - one `col_of` overload per scope (198), with no catch-all, so a wrong name is a type error.
- `python/tfscan/schema.py` (1,914 lines): the same aliases and TypedDicts plus an `ATTRIBUTES` table and a runtime `col_of` that raises `KeyError` on a wrong name.

At generation time the allowlist had 16 entries from aws, google, cloudflare, kubernetes and github; azurerm has no allowlist entry. That gave 16 types and 198 scopes. Example (from the generated file):

```python
AwsSecurityGroupIngressAttr = Literal["cidr_blocks", "description", "from_port", "ipv6_cidr_blocks", "prefix_list_ids", "protocol", "security_groups", "self", "to_port"]
class AwsSecurityGroupIngress(TypedDict, total=False):
    cidr_blocks: list[str]
    from_port: float
    ...
@overload
```

`mypy --strict` (2.4.0) accepts a typed rule and rejects `col_of("aws_security_group.ingress", "frm_port")` ("No overload variant of "col_of" matches argument types "str", "str"") and `{"from_port": "22"}` ("TypedDict item "from_port" has type "float"") (`test_stubs.py`; [A3](#a3-pytest)). `mypy -p tfscan` on the installed package reports no errors after a `type: ignore` for untyped pyarrow. The extension-module stub `_tfscan.pyi` is hand-written.

## Scope cuts and known gaps

- **IR v1 expressiveness.** There are no string functions (prefix, regex, CIDR containment), no arithmetic, no cross-resource joins or module-level rules, and no traversal into `jsonencode` / heredoc JSON documents. `col` into a `Known::Json` value is an error and therefore Unknown, so no finding. As a result, seed rules 2 (S3 public-access-block join) and 3 (IAM wildcard policy) **cannot** be written in the expression API; rules 1, 4 and 5 can, and match the built-ins. Message templates have no conditionals. *Why cut:* seed rule 1 was the exit criterion. Adding `module` scopes with joins and JSON-path ops is the obvious IR v2.
- **Callbacks.** The resource is cloned per call (`Arc<Resource>`). Values in callbacks carry provenance labels but no file and line, because the scan's `FileTable` is not reachable from inside the engine. Callbacks serialise on the GIL and get slower with more threads (measured above). Callbacks cannot run with the test-only `_release_gil=False`.
- **Arena AST prototype.** It is read-only, has no Python-side visitor, creates a Python object per node handle, and is not connected to the semantic model (no node ids on `Resource`). Its two `unsafe impl`s rely on bumpalo internals.
- **Arrow.** Attributes are a JSON string column, not typed structs, because resource types have different schemas. A per-type table with the stub generator's TypedDict shapes is possible but was not built. Per-resource JSON dominates export time.
- **Packaging.** The wheel is `manylinux_2_34_x86_64` only: it was built on this machine, with no manylinux container or zig, and no macOS or Windows builds. `maturin build` was not run through `pip install` of an sdist. abi3 wheels do not support free-threaded CPython.
- **CLI.** `oxtf rules` does not list `--rule-file` rules.
- **Coverage of the corpus comparison.** The corpus has no sg-open-ssh findings, so the discriminating evidence is the generated differential corpora: 4 seeds, 4,200 roots and 6,086 findings in the tables above, plus seed 7 in pytest.
