## Design

### Rule trait and engine

```rust
pub trait RuleMeta {
    const NAME: &'static str;                       // "aws-sg-open-ssh"
    const CATEGORY: Category;                       // Network | Storage | Iam | Encryption
    const LEVEL: Level;                             // Low | Medium | High | Critical
    const DESCRIPTION: &'static str;
    const RESOURCE_TYPES: &'static [&'static str] = &[];   // dispatch keys for run_on_resource
    const RUNS_ON_MODULE: bool = false;                    // cross-resource rules
}
pub trait Rule: RuleMeta + Send + Sync {
    fn run_on_resource(&self, _: &Resource, _: &mut RuleContext<'_>) {}
    fn run_on_module(&self, _: &Module, _: &mut RuleContext<'_>) {}
}
pub trait DynRule: Send + Sync {                     // object-safe; blanket impl for every T: Rule
    fn info(&self) -> RuleInfo;                       // owned metadata (name, category, level, types, runs_on_module)
    fn run_on_resource(&self, r: &Resource, ctx: &mut RuleContext<'_>);
    fn run_on_module(&self, m: &Module, ctx: &mut RuleContext<'_>);
}
```

`Linter::new(Vec<Box<dyn DynRule>>)` builds `HashMap<resource type, Vec<rule index>>` and the list of module rules once. `Linter::run(&Analysis)` visits every module instance (root and local children): module rules first, then each managed resource whose `existence` is not `False` is dispatched to the rules registered for its type. A rule written in Rust is a unit struct with two trait impls (see `rules/aws_rds_unencrypted.rs`, 39 lines); a rule compiled at runtime from a Python expression (W6) implements `DynRule` directly, so it plugs into the same table and runs on rayon workers without the GIL.

Rules see the **owned, evaluated model** from `tf_semantic` (`Resource`, `Body`, `Attr`, `tf_eval::Value`), never the arena AST, so findings, rules and the model are `Send + Sync` and the model can be handed to Python as is.

`RuleContext::report(resource, &Verdict, message)` turns a four-valued `Verdict` (from `tf_eval::truth`) into a finding:

- `Truth::True` → `Severity::Definite`; `Truth::Tainted` → `Severity::Conditional`; `Unknown` / `False` → nothing.
- A definite verdict on a resource whose `existence` is `Tainted` (`count = var.x ? 1 : 0` with `var.x` unconstrained) is downgraded to conditional; `existence = False` never reports.
- The provenance chain is the witness value's chain (origin first). The primary span is the newest chain step that belongs to the reported resource (usually the attribute that decided it), else the resource header.
- Conditional messages name the unconstrained variable when the witness is `Tainted(var)`.

Predicates are written with `tf_eval::truth`: `test(value, |known| bool)`, `exists(list, |elem| Verdict)`, `map(value, |known| Verdict)` (lifts over `OneOf`), and `Verdict::and / or` (`min` / `max` over `False < Unknown < Tainted < True`, keeping the deciding witness).

### Severity semantics

*Definite* = the predicate holds for the configuration as written, with variable defaults, tfvars / var-files, and the defaults overlay for absent attributes. *Conditional* = it holds for some value of an unconstrained variable (no default, no tfvars value), i.e. the verdict is `Tainted` (see W3.md for the exact Tainted rules). Values only known at apply time (computed attributes, remote module outputs, unsupported functions) produce no finding: the engine prefers false negatives to noise there.

### Scanning, parallelism, root selection

`scan_with(&Linter, roots, &ScanOptions)` analyses each root module on a rayon pool (default: one thread per CPU; 4 MiB stacks, sized from the measured recursion bound in docs/LIMITS.md) with a shared, thread-safe `FileTable` so `FileId`s are global to the scan; it returns `(ScanResult, Vec<Analysis>)`.

**Module roots** (`discover_roots`): without `--recursive`, the given directory is the root module. With `--recursive`, every directory under the path that contains at least one `.tf` file is a root module (hidden directories such as `.terraform` are skipped). Consequence, documented rather than deduplicated: a module directory that is also called by an example is analysed twice, once standalone (its variables from defaults, unset ones unconstrained) and once inside each local caller (its resources then have addresses like `module.db.module.db_instance.aws_db_instance.this`), so the same source line can produce findings in several contexts. Each finding records the `root` it came from.

### Rendering

`render::render_finding` builds a miette `Diagnostic`: code `rule-id [severity]`, severity Error (definite) / Warning (conditional), the primary file as source with the primary label, other provenance steps in that file as secondary labels numbered `[i/n]`, steps in other files as `related` diagnostics with their own source, and a `help:` line with the whole chain (`label (file:line) -> ...`). `render::result_json` emits findings (with `location` and `provenance[]` entries: file, line, column, byte span, kind, label), diagnostics and stats.

## The five rules

| rule | resource types | semantics |
|---|---|---|
| `aws-sg-open-ssh` (High) | `aws_security_group`, `aws_vpc_security_group_ingress_rule`, `aws_security_group_rule` | Some ingress rule is open (`0.0.0.0/0` or `::/0` in `cidr_blocks` / `ipv6_cidr_blocks`, or `cidr_ipv4` / `cidr_ipv6`) **and** reaches port 22: protocol `-1` / `all`, or `tcp` / `6` with `from_port <= 22 <= to_port`. Inline `ingress` comes from block syntax (attributes-as-blocks), `dynamic "ingress"` (expanded; unknown `for_each` gives a maybe-absent abstract rule), or the attribute form. `aws_security_group_rule` additionally needs `type = "ingress"` (an addition beyond the fixtures). Witness: the open CIDR element. |
| `aws-s3-public-access-block` (High, module rule) | `aws_s3_bucket` × `aws_s3_bucket_public_access_block` in the same module instance | Join: a PAB refers to a bucket if its `bucket` value is `Unknown { Computed { resource: <bucket address>, attr: id | bucket } }` (instance keys compatible), or its provenance passes through the bucket's `bucket` attribute, or it is a Known string equal to the bucket's Known name. Unresolvable PAB `bucket` values (remote module, tainted, provider-chosen bucket names) are "maybe" matches; with no definite match but a maybe match, the bucket is not reported. No matching PAB → definite. With matches: insecure iff some flag of `block_public_acls`, `block_public_policy`, `ignore_public_acls`, `restrict_public_buckets` is not `true` (absent → overlay default `false`); a secure PAB wins over a permissive one (AND over matches); a PAB whose existence is tainted adds `Tainted`. |
| `aws-iam-wildcard-policy` (Critical) | `aws_iam_policy`, `aws_iam_role_policy`, `aws_iam_user_policy`, `aws_iam_group_policy` | `policy` as a document: the structured argument of `jsonencode` (inline, via locals, via `for` over a variable), a JSON string / heredoc (parsed with serde_json, provenance of the string), or `data.aws_iam_policy_document.*.json` (rendered by the semantic layer; added in W4). Fires when some `Statement` (object or list) has `Effect = "Allow"`, `Action` `"*"` (string or list element) and `Resource` `"*"`. Deny statements, `NotAction` / `NotResource` and partial wildcards (`s3:*`) do not fire. Witness: the `"*"` action element. |
| `aws-rds-unencrypted` (High) | `aws_db_instance` | `storage_encrypted` not `true`; absent or `null` uses the defaults overlay (`false`). Read replicas (`replicate_source_db` set) are skipped (encryption is inherited); an addition beyond the fixtures. |
| `gcp-storage-uniform-access` (Medium) | `google_storage_bucket` | `uniform_bucket_level_access` not `true`; absent or `null` uses the overlay (`false`; the attribute is optional+computed, so an org policy can still force it, as noted in the overlay). |

**Getting evaluated attribute values (example).** `let (r, analyses) = scan_dir_with_model(dir, &opts); for a in &analyses { for m in &a.modules { for res in &m.resources { res.value("storage_encrypted") ... } } }`. Nested attributes written as blocks (`ingress`) are list-of-object values on `res.body.attrs`; real nested blocks are `res.body.blocks`.

**How to define a rule (what a Python expression must compile to).** Implement `DynRule`: `info()` returns `RuleInfo { name, category, level, description, resource_types, runs_on_module }`; `run_on_resource(&Resource, &mut RuleContext)` computes a `tf_eval::Verdict` from attribute values with `truth::test` / `exists` / `map` and `Verdict::and` / `or`, and calls `ctx.report(resource, &verdict, |witness| message)`. A rule IR therefore needs: attribute access (`value`, `value_or_default`, `field` into objects), element quantifiers (`exists` over lists), scalar predicates on Known values (equality, membership, numeric comparison, string prefix), boolean combinators, and a message template. Seed rule 1 in this vocabulary is `exists(ingress, r => (exists(r.cidr_blocks, c => c in OPEN) or exists(r.ipv6_cidr_blocks, ...)) and (r.protocol in ANY or (r.protocol in TCP and r.from_port <= 22 and r.to_port >= 22)))`. Nothing in the engine requires Rust closures, so an interpreted IR node tree fits; module (cross-resource) rules would need a join operator.

## Scope cuts and known gaps

- **Spot-check size.** The corpus yields 2 findings, so "spot-check ~10 findings" became "both findings + 10 rule-evaluated non-findings" (above).
- **Additions beyond the fixtures** (kept small, documented): `aws_security_group_rule` in the SSH rule; read-replica exemption in the RDS rule; `aws_iam_policy_document` rendering (+2 fixtures).
- Not handled: `NotAction` / `NotResource` / partial wildcards in IAM; inline `aws_iam_role.inline_policy`; S3 account-level public access block (`aws_s3_account_public_access_block`) and bucket policies/ACLs; SSH via `aws_network_acl` or prefix lists; port ranges given as strings are compared numerically (`"80"` parses), protocol names other than tcp/6/-1/all (e.g. `"tcp "`) are trimmed only for whitespace.
- Remote module outputs never produce findings (Unknown). A finding inside a module directory appears once per root that instantiates it (no cross-root deduplication); `root` tells them apart.
- Exit code does not reflect findings (no `--fail-on` flag yet). No SARIF.
- `count` > 1 instances are represented by one instance (no per-index findings).
- No changes were made to tf_ast / tf_parser / tf_schema.
